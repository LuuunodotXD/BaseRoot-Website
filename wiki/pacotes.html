Pacotes

O BaseRoot tem dois gerenciadores de pacotes: o dumpkg (com dependencias e checksum) e o spkg (o minimo possivel). Os pacotes disponiveis estao na Lista de pacotes.

DUMPKG

O dumpkg eh um gerenciador de pacotes binarios minimalista escrito em shell POSIX puro. Funciona atraves de receitas (.binfile) com informacoes do pacote, URL de download, checksum e dependencias. Nao resolve dependencias automaticamente por padrao, mas a flag -d instala tudo na ordem certa: o dumpkg mostra a install order antes de comecar.

Principais funcionalidades:

  • dumpkg-install <pkg> -- instala um ou mais pacotes
  • dumpkg-install -d <pkg> -- instala com dependencias, na ordem certa
  • dumpkg-remove <pkg> -- remove um ou mais pacotes
  • dumpkg-update -- sincroniza receitas e atualiza pacotes
  • dumpkg list -- lista pacotes instalados
  • dumpkg search <pkg> -- pesquisa no repositorio
  • dumpkg deptree <pkg> -- exibe arvore de dependencias
  • dumpkg verify <pkg> -- verifica integridade dos arquivos

Cada pacote baixado eh conferido pelo checksum antes de ser extraido. Exemplo completo: 

dumpkg-update
dumpkg search firefox
dumpkg deptree firefox
dumpkg-install -d firefox

Codigo-fonte disponivel em: www.github.com/LuuunodotXD/Dump-Package-Manager

spkg

O spkg eh um gerenciador de pacotes alternativo e ainda mais simples, compativel com o shell do toybox. Usa um repositorio no formato JSON e nao depende de receitas -- apenas uma lista de pacotes com nome, versao e link de download. De proposito, nao resolve dependencias nem confere checksum: eh para quem quer o minimo. Quando precisar disso, use o dumpkg.

Comandos:

  • spkg sync -- sincroniza o repositorio
  • spkg add <pkg> -- instala um ou mais pacotes
  • spkg del <pkg> -- remove um ou mais pacotes
  • spkg up -- atualiza todos os pacotes
  • spkg list -- lista pacotes instalados

Firefox

O Firefox ESR 153.7.0-esr eh o build do Alpine Linux (que tambem usa musl), reempacotado para o BaseRoot. Como o repositorio ja tem GTK, X11, Mesa e fontes, o pacote firefox declara so o que falta como dependencia. 

dumpkg-install -d firefox
startx            # e, no xterm:
firefox

Para funcionar bem:

  • Um kernel com user namespaces, seccomp e SysV IPC (veja Kernel) e /dev/shm montado.
  • Dentro do QEMU, ligue o KVM (-cpu host -enable-kvm); o CPU generico do QEMU eh lento e pode faltar instrucao.
  • Os avisos glx: failed to create dri3 screen e failed to load driver: virtio_gpu sao normais no QEMU: o Firefox usa renderizacao por software.
  • O aviso do dbus-launch some abrindo com dbus-run-session firefox.

Receitas (.binfile)

Uma receita eh um arquivo de texto simples, um campo por linha (campo=valor). Exemplo do nss: 

name=nss
version=3.133
description=Network Security Services: TLS and certificates
url=https://raw.githubusercontent.com/LuuunodotXD/Dump-Packages/main/main/nss-3.133.tar.gz
compression=gzip
md5=...
sha256=...
deps=nspr sqlite-libs zlib
postinstall=
conffiles=
CampoSignificado
name, version, descriptionidentificacao do pacote
url, compressiononde baixar o tarball (gzip ou bzip2) e como descomprimir
md5, sha256checksums conferidos antes de instalar
depsoutros pacotes, separados por espaco (usados por -d)
postinstallum comando, em uma linha, rodado depois da extracao (sem o caractere =)
conffilesarquivos de configuracao que nao devem ser sobrescritos

As receitas ficam em Dump-Package-Recipes e os binarios em Dump-Packages. Pacotes muito grandes (como o Firefox) ficam nos Releases do GitHub.
